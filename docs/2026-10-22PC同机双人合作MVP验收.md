# PC 同机双人合作 MVP：实现与验收

日期：2026-10-22，双向托举更新：2026-10-27。基于本仓库 Phaser 3.90.0、Arcade Physics、TypeScript 5.9 与 Vite 7，复用现有角色、森林资源、音效及单向平台判断。未接入服务器，不改主线地图、地图工坊格式和单人存档。

## 入口与玩法

电脑打开页面，在主菜单点击“同机双人”或按 C。准备页固定 P1 为一二、P2 为布布；P1 按 E、P2 按 Enter，各按一次并松开后开始。原有单人开始/继续和星光体验入口保留。

| 玩家 | 左右移动 | 跳跃 | 互动 | 技能 |
| --- | --- | --- | --- | --- |
| P1 一二 | A / D | W | E | 按住 F 托举 |
| P2 布布 | ← / → | ↑ | Enter | 按住右 Shift 托举 |

公共 Esc 暂停/恢复；暂停页可继续、重开、返回菜单；通关页可重开、返回菜单。页面失焦自动暂停，恢复需要主动操作。手机和平板在游戏引擎加载前展示“当前版本仅支持电脑，请使用电脑浏览器并连接键盘游玩。”，PC 小窗口不因宽度被阻挡。

教学路线为跑跳练习 → 任意一人托举队友 → 队友借力登高开桥 → 经桥汇合 → 两人分别占用压力开关永久开门 → 共同到营地激活检查点 → 小坑掉落/跳跃练习 → 两人共同到金色终点。

普通跳高按现有参数计算为 `590² / (2 × 1450) ≈ 120px`，高台比地面高 176px，超过单人从地面起跳的范围。乘坐者从队友头顶起跳时仍只获得原有 `-590` 跳速，合作收益完全来自高出约一个角色身体的起跳位置；因此这段地形是“单人跳不过、托举后可达”，而不是给角色额外的跳跃技能。普通跑跳的速度、重力、离台宽限和跳跃缓存均未修改。

检查点前设集合门，防止一人提前进入跌落区；检查点激活后各有独立安全出生位置。桥、压力门和集合门在本次挑战内持续开启，单人复活不重置；重开重新创建规则状态。终点只有两人正常落地并处于终点区时才结算，重复帧不会再次结算。

## 架构与关键文件

| 文件 | 用途 |
| --- | --- |
| `src/main.ts`、`src/GameApp.ts`、`src/systems/DesktopGate.ts` | 先判断设备，再按需加载引擎；保留原有启动和销毁逻辑 |
| `src/scenes/StartScene.ts` | 单人入口保留；新增懒加载双人入口及失败重试 |
| `src/config/coopControls.ts`、`src/types/commands.ts` | 集中键位与玩家语义指令，玩家 ID 和角色 ID 分离 |
| `src/systems/CoopKeyboard.ts` | 独立按下/保持/松开状态；暂停、失焦、文本输入与监听销毁 |
| `src/entities/Player.ts` | 单人和双人共用角色移动实现；默认手感不变，增加合作移动倍率及乘坐物理交接 |
| `src/config/coopLift.ts`、`src/systems/PlayerCooperationController.ts` | 双向状态机、唯一承载关系、捕获/跟随/借力跳、空间检查和生命周期清理 |
| `src/systems/CoopLiftAnimator.ts` | 将托举准备和承载状态映射到两名角色各自的一张静态托举姿态，不参与物理规则 |
| `src/levels/coopTutorial.ts`、`src/systems/CoopRules.ts` | 独立教学数据、稳定机关 ID、目标优先级、检查点和一次性通关规则 |
| `src/scenes/CoopScene.ts` | 两角色实例、机关表现、单人复活、安全距离、暂停与流程管理 |
| `src/systems/CoopCamera.ts` | 平滑关注双人位置、缩放和地图边界，复活中跟随安全出生点 |
| `src/systems/CoopOverlay.ts`、`src/systems/coop.css` | 世界镜头之外的 DOM 准备页、HUD、暂停与结算 |
| `tests/coop*.test.mjs`、`tests/helpers/coop-runtime.mjs` | 输入与设备测试、实际 Arcade CPU 物理与完整教学流程测试 |

输入层不直接操作机关，角色消费语义指令，规则消费玩家状态和目标 ID，场景处理表现及物理接入。后续联机可替换输入源，本轮未加入网络、房间或同步框架。

共享镜头基础缩放随窗口计算，允许缩至其 0.72 倍；距离 440px 起提示，560px 起在安全地面限制向外走，允许靠近队友。空中不截断水平速度。检查点后另有前进范围约束，保证旧营地复活者仍能与队友汇合。HUD 不受镜头移动/缩放影响。

## 已完成的自动验证

`pnpm test:coop` 可单独复现双人专项，`pnpm verify` 依次执行 ESLint、全部测试、TypeScript 检查、Vite 构建及产物预算检查。

自动物理测试使用已安装的真实 Arcade World、Body、StaticBody 和 Collider，按引擎物理更新、场景更新、物理后更新的顺序驱动；碰撞尺寸从仓库角色图片解码得出。渲染、音频和相机调用使用适配器，因此这些结果不等于浏览器/GPU 实玩验收。

| 项目 | 自动验证内容 |
| --- | --- |
| 准备与输入 | 准备必须双人按键并松开；独立移动、跳跃、互动/技能按下、保持、松开；左右 Shift 区分；P1 F 与 P2 右 Shift 互不串键 |
| 暂停与焦点 | 暂停冻结流程计时；失焦清输入；文本输入不阻止默认键位且不会被暂停 UI 抢焦点；窗口外漏掉 keyup 后新按键可恢复 |
| 托举 | 两个方向均可按住准备、从上方捕获、低速移动及稳定跟随；松键立即安全解除；上升/侧面/下方/过快坠落不吸附；低天花板阻挡；头顶起跳只赋值一次原跳速 |
| 边界与复活 | 托举者掉落立即解除；双人同时复活不重叠；单人掉落后另一人位置及机关进度保留 |
| 全关通路 | 用键盘事件与真实物理依次完成托举高台、开桥、布布汇合、双开关、共同营地、掉落复活、跨坑和共同终点 |
| 幂等与清理 | 终点胜利音效只调用一次；重复导航只启动一次；场景销毁后 DOM、场景/游戏监听清理并归还键盘设置；重复创建/销毁输入无旧监听响应 |
| 帧率 | 30、60、120Hz 更新条件下双向托举进入、移动跟随、头顶起跳与松键解除 |
| 镜头 | 常见宽高比的缩放计划和边界计算、HUD 独立挂载；安全地面向外限制、允许靠近；空中保留正常动量 |
| 设备与构建 | iPhone、Android、iPad 桌面 UA、触屏 Windows PC、小窗口 PC；入口约 3KiB 且 HTML 不预加载 GameApp，双人场景按需加载 |
| 既有回归 | 单人两角色与两关流程、战斗/暂停、存档、资源失败恢复、星光/护盾及地图编辑器已有测试 |

本轮测试发现并修复：暂停反馈抢走输入框焦点；失焦期间丢失松键事件后首次新按键被屏蔽。之前准备测试失败是 jsdom 默认不可见，已改为可见页面环境。构建仍有包含 Phaser 的游戏主包超过 Vite 默认 500kB 警告，项目现有包预算检查通过。

## 待人工验收与表现资源

以下项目尚未实际验证，不能作为上线验收已通过项：

- 同一实体键盘多键并发和硬件冲突：两人同时方向、跳跃、互动及右 Shift；不同键盘和输入法。
- Chrome / Edge 实玩全通、反复暂停、切标签页、窗口失焦后恢复，及至少三次重开/返回菜单/重进双人。
- 16:9、16:10、4:3、超宽屏和 PC 小窗口下准备卡片、HUD、提示文字及镜头视觉边界；真实 resize 的平滑效果。
- WebGL / Canvas 实际渲染、角色/平台对齐、音频解锁与音量、界面遮挡、真实帧率和性能。
- 手机和平板真机在横竖屏、桌面 UA 下显示提示且不加载大批游戏资源。
- 托举贴边、低天花板、移动跟随、反向托举、借力跳和死亡时的实玩手感。自动测试覆盖逻辑边界，但不替代实际操作体验。

当前每名角色只加载一张透明背景的静态托举姿态，托举准备与承载共用，不循环播放；一二和布布使用相同的正面身体方向、双脚位置与双臂承托构图，只保留角色形象差异。姿态按原角色待机轮廓等比缩放、居中并对齐脚底，碰撞框仍保持固定。乘坐者复用原待机表现，借力起跳和取消托举回到原跳跃/待机表现。桥梁、门和机关目前为现有纹理/简单色块占位，可在玩法验收后替换表现。首版没有救援、小伞、牵手或抛掷，也没有双人主线选关或通关存档。
