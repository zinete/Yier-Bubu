# 星光特效与唤醒玩法 MVP

日期：2026-10-19。本轮按前述“两步落地”顺序实现：先增强现有技能反馈，再增加星光唤醒体验关和编辑器支持。没有改变正式两关的伤害、攻击冷却、跳跃参数或解锁规则；本轮未自动提交或部署。

## 怎么体验

1. 启动 `pnpm dev`。主菜单选择角色后，点击“星光唤醒体验关”，或按 **3**；不需要先解锁正式关卡。
2. 向右移动，使用 **J / 手机投掷按钮**击中金色花苞，让虚线跳台成为实体；跳过三段断桥，三朵花均至少点亮一次后星门解锁。
3. 平台每次激活维持 **8 秒**，可重复射击续时；最后 **1.5 秒**会显示“即将休眠”，然后恢复虚线且取消碰撞。不要把透明虚线当作可站立台面。
4. 中段有检查点。暂停、切后台或旋转到竖屏时，平台倒计时与游戏模拟时间一起冻结；继续后恢复，不按现实时间扣除。
5. 设置菜单或游戏暂停菜单 → **画面与特效**，可切换质量、减少动态效果。关闭设置后需要手动继续游戏。

体验关长度 2880px，设计目标约 30 秒游玩，时间限制放宽为 90 秒；实际通关耗时尚未实测。体验关胜负/重玩不会写入正式两关的解锁或最高分。两个角色继续共用原有能力，不在此版本强行拆分角色技能。

## 第一步：现有技能表现

- 聚光：薄荷绿与蜂蜜金星屑收拢、短时光圈；仍采用原来的 140ms 发射准备，不是新的长按蓄力机制。
- 飞行：保留对象池与星星拖尾；丰富 WebGL 档为弹体附加局部 Pre FX 辉光，每次复用不重复添加。
- 命中：星屑散开、柔和扩散环；丰富 WebGL 档增加约 320ms 的相机冲击波着色器，不扭曲独立 UI 场景。
- 检查点/花苞：双层暖色光圈与更密集星花反馈。

没有增加弹体伤害、穿透或击退，也未实现长按强化弹，避免表现升级与数值修改混为一谈。

## 第二步：玩法与编辑器

- 放置面板新增 **星光平台（花苞唤醒）**，每个对象包含一朵花苞与一块限时跳台，支持连续放置。
- 选中平台后可开启/关闭唤醒属性；星光参数收纳在折叠区，设置持续时间、花苞相对 X/Y。
- 平台和花苞一起移动、复制、粘贴、删除、撤销、保存/导出；编辑器用引导线表示配对，不是任意多个机关的连接图。
- 地图设置可勾选“唤醒所有花苞后才能通关”。删除最后一朵花时会同步解除无效的终点锁；撤销恢复完整配置。
- 自定义平台沿用现有外观素材/拼接与站立面规则；休眠时只显示虚线位置，不存在隐藏碰撞。
- 提供可导入的样例：`maps/starlight-awakening-30s.json`。它与主菜单体验关采用相同布局；导入为自定义地图后从结算返回工坊。

### 数据扩展

沿用 CustomMap v1 的可选扩展，旧地图不含字段时维持原行为：

```json
{
  "kind": "platform",
  "x": 608, "y": 432, "width": 160, "height": 32,
  "awakening": { "budOffsetX": 16, "budOffsetY": -32, "durationMs": 8000 }
}
```

`level.awakeningGoal: true` 表示所有花苞至少点亮一次后解锁终点，不要求同时保持亮起。平台休眠不清除“已点亮一次”的记录；重玩关卡会重置。

约束：最多 20 个星光平台；每个平台 3000–30000ms；花苞必须在世界范围内；地面不可变为休眠平台。出生点、检查点、终点必须由永久平台承接。花苞触发框为 32×32，编辑器的相对位移按 16px 网格吸附；外部旧坐标仍按现有导入策略兼容。

## 降级、预算与生命周期

- 自动档：桌面 WebGL 开启辉光/冲击波，触控设备减少粒子并关闭这两项 GPU 特效；手动丰富档可开启，但不承诺未实测手机的帧率。
- 精简档/Canvas：保留必要轮廓、少量粒子、倒计时、休眠警告和全部物理规则，不使用 GPU 特效。
- 减少动态效果默认读取系统偏好，可手动覆盖；关闭震屏、冲击波和聚光轨迹/大幅光圈缩放。仍保留必要文字与少量反馈，不是完全无动画模式。
- SkillEffects 自身的瞬态图片最多 16 个，粒子沿用有上限的发射池，相机最多一个短时冲击波；不把这些局部预算说成整个场景对象上限。
- 切换精简档清理旧辉光；暂停移除冲击波，退出场景退订设置、清理动画和自有 GPU 管线，不清除其他管线。
- GPU 管线创建/初始化抛异常时回退普通效果；新增 `?renderer=canvas` 便于明确检查 Canvas 路径。不等于已验证所有驱动的编译和上下文丢失行为。

## 验收与边界

自动检查：`pnpm verify`。包括现有回归，以及花苞激活/续时/失效、目标锁、正式存档隔离、暂停时间、敌方弹体过滤、同弹体一次触发、地图往返、编辑器操作、特效预算/相机滚动坐标/清理、设置窗口与存储降级。

模拟适配器测试执行真实控制器、场景和特效生命周期方法，但不执行 WebGL shader、不渲染真实浏览器画面，也不是实际物理逐帧通关。以下仍需人工验收：

- [ ] 桌面 WebGL 冲击波编译与中心位置、画面边缘、缩放/滚动后效果。
- [ ] 手机自动档/丰富档的实际帧率、发热与点击区。
- [ ] 桌面与手机分别真实通过体验关，检查三段跳跃、花苞瞄准和检查点。
- [ ] `?renderer=canvas` 完整通关；精简/减少动态效果下仍能明确识别休眠与激活。
- [ ] 连续重玩 10 次，暂停/设置/切后台/旋屏后不粘键、不重复监听、不遗留后处理。

浏览器/GPU/真机实测未执行前，不把上述清单勾选为通过。此 MVP 不代表 0.1 发布门槛已全部完成。

本机记录：`pnpm verify` 已通过 lint、21 个测试脚本、TypeScript/Vite 生产构建和产物检查；`git diff --check` 无空白错误。主 JS 约 1318 KB（gzip 370 KB），工坊 JS 约 96.5 KB；全部静态产物约 20.13 MiB，不是首屏传输量。未增加位图下载，星花/光环用程序生成纹理。Vite 主包超过 500 KB 的既有提醒仍在，不以检查通过代表手机 GPU 或加载性能达标。
