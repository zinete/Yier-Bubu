# 《一二布布冒险记》开发迭代计划

> 版本：v1.0（2026-10-12）  
> 项目：Phaser 3 + TypeScript + Vite 横版冒险游戏  
> 用途：作为后续开发排期、验收与回归测试的共同基线。

## 1. 当前项目结论

项目已经完成可玩的 **首关 MVP**：开始页可选一二/布布、角色跑跳、投掷、踩踏敌人、金币、生命/倒计时 HUD、暂停、结算页及触屏虚拟按键均已具备。核心实现位于 `src/scenes/GameScene.ts`，关卡数据位于 `src/levels/level1.ts`。

当前代码质量基线：`pnpm lint` 已通过。`pnpm build` 的 TypeScript 检查已开始执行，但 Vite/esbuild 在受限环境读取上级目录时被拒绝，未能完成打包；应在本机常规终端或 CI 中复跑，以区分环境权限与真实构建问题。项目暂未配置单元测试、端到端测试或 CI。

工作区另有未提交改动：`Enemy.ts`、`Projectile.ts`、`GameScene.ts` 增加了敌人远程投掷和敌我发射物区分。这项功能应作为迭代 1 的首个验收对象；计划不覆盖这些现有修改。

## 3. 迭代目标与优先级

开发顺序遵循“可稳定游玩 → 可持续闯关 → 可发布体验”。每个迭代完成后应保留可演示版本并完成对应验收，避免内容扩展掩盖基础玩法问题。

### 迭代 1：战斗闭环与首关稳定性（P0）

**目标**：使 1-1 从开始到结算稳定可玩，敌我攻击行为明确且不产生误伤或卡关。

工作项：

- 完成并人工验证当前敌人远程攻击改动：攻击距离、冷却、朝向、敌方弹体命中、玩家无敌帧、死亡后停止攻击。
- 将敌人攻击距离、冷却、弹速等从实体常量迁至关卡/敌人数据；明确不同敌人类型的扩展接口。
- 校验发射物对象池复用、过期回收、碰撞平台回收，以及敌方弹体不会伤害敌人、玩家弹体不会伤害玩家。
- 修复首关可复现问题（坠落回检查点、暂停/重开后状态、计时结束与结算的竞态）。
- 为首关建立手工回归清单，并记录已知问题。

验收标准：

1. 键盘与触屏均可从开始页进入 1-1，并完成或失败后再开一局。
2. 敌人仅在有效距离及冷却结束后发射；被踩踏或命中后不再攻击。
3. 每一颗弹体只结算一次命中，超时、出界、命中平台后消失；连续游玩 10 分钟不出现显著的弹体累积或报错。
4. 暂停时角色、敌人、倒计时与攻击全部停止；恢复后继续。
5. `pnpm lint`、`pnpm build` 在常规本机或 CI 环境通过。

### 迭代 2：进度系统与第二关（P0）

**目标**：形成至少两关连续可玩的最小游戏流程。

工作项：

- 建立 `LevelRegistry`（或同等机制），统一按关卡 id 读取关卡数据，移除 `GameScene` 对 `level1` 的硬编码。
- 新建 `level2.ts`，包含不同节奏的平台、敌人、奖励路线和检查点，并通过 `LevelValidator`。
- 用 localStorage 保存最高解锁关卡、当前关卡与关卡最佳分数/全收集状态；增加版本号和损坏数据降级。
- 扩展结算页：胜利后显示“下一关/重玩/返回主页”，最后一关提供完整通关反馈。
- 开始页提供继续冒险及已解锁关卡入口；未解锁内容有明确状态。

验收标准：

1. 首次打开只能进入 1-1；通关 1-1 后解锁并可进入 1-2。
2. 刷新页面后，解锁关卡和最佳记录仍保留；清除浏览器存储后恢复初始状态。
3. 两关均不存在无解的主线路径；第二关能从入口抵达终点。
4. 结算页所有按钮可用，且场景切换后 HUD、事件监听、定时器不重复创建。

### 迭代 3：反馈、音频与可访问性（P1）

**目标**：提升操作反馈与完成感，使基本设置真实生效。

工作项：

- 接入已获授权的 BGM 和音效（跳跃、投掷、受伤、收集、胜负），补齐 `PreloadScene` 资源加载和资源加载失败降级。
- 将声音与音乐开关、音量分别暴露到设置页，并持久化。
- 增加受伤闪烁/击退、命中粒子、金币收集提示、敌人攻击前摇等可读反馈。
- 补充键盘操作提示，确保所有核心行为不依赖鼠标；检查文字对比度与触控热区尺寸。
- 在常见桌面与移动横屏尺寸上校验 HUD、安全区、虚拟按键和横屏引导。

验收标准：

1. 有音频资源时可听到对应事件；无音频或自动播放受限时游戏仍可正常开始。
2. 音效/音乐开关及音量刷新后保持；失焦暂停音乐、回到页面后按设置恢复。
3. 角色受击、敌人射击、收集与通关均有不依赖声音的视觉反馈。
4. 在 360×640、390×844、768×1024、1366×768 等视口中，不遮挡核心 HUD 或操作按钮。

### 迭代 4：质量、性能与发布准备（P1）

**目标**：让后续关卡扩展和交付可重复验证。

工作项：

- 为纯逻辑补充单元测试：关卡校验、存档迁移、进度解锁、战斗配置边界。
- 引入浏览器端冒烟测试：启动、选角、进入关卡、暂停、失败重开、通关跳关。
- 配置 CI：安装依赖、lint、类型检查、生产构建与测试。
- 建立性能基线：目标设备中 60 FPS（或明确降级策略）、无控制台异常、长时间游戏内存稳定。
- 补充发布清单：版权/授权资源、版本号、构建产物、浏览器兼容性、已知限制。

验收标准：

1. 每次合并前自动完成 lint、类型检查、构建和核心测试。
2. 支持的 Chrome、Edge 与移动浏览器完成一轮冒烟用例且无阻塞问题。
3. 连续游玩 20 分钟、反复重开与切关后不出现致命异常或明显性能退化。

## 4. 建议的开发拆分与依赖

```text
迭代 1：战斗稳定 ────────────────┐
                                  ├─> 迭代 2：关卡注册 + 存档 + 1-2
基础配置/关卡数据结构 ────────────┘             │
                                                ├─> 迭代 3：反馈与音频
                                                └─> 迭代 4：自动化与发布
```

建议每个工作项以独立分支/提交完成，并在 PR 或提交说明中附上：变更范围、验收截图/录屏、执行命令及结果、已知限制。第二关地图和授权音频是需要产品/美术侧提供或确认的外部输入；在拿到前可先完成框架、占位资源与测试。
