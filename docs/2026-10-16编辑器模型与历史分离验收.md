## 用户可见变化

- 含上传图片的地图不再将撤销限制为 10 步，统一最多保留 50 次有效操作；拖动、批量操作和连续滑块仍一次交互一次撤销。
- 顶栏显示「撤销 / 重做 / 共享图片」数量。鼠标停留可查看差量与图片字符串的估算体积；不将该数值当成整个游戏占用内存。
- 上传、导入、新建、删除、复制与重做不需要改变使用方式。文件仍为版本 1、自包含 JSON，图片仍内嵌，可直接分享与导入。
- 每个玩法对象有地图内唯一的 `objectId`，复制生成新编号，移动/编辑/撤销/导入导出保持编号。单选属性摘要的悬停提示可查看编号。

## 实现与边界

### 可编辑模型与共享图片池

`EditorDocument` 将图片原始字符串集中按内容去重；内存快照、拖动起点、保存状态基线只记录素材元信息与内部图片引用。不同素材 ID 使用相同图片内容时共享同一载荷；同一素材 ID 在导入后更换内容时，新旧载荷分别保留以供撤销。

候选模型克隆只深复制关卡、对象、图层、材质等可编辑数据；图片字符串共享、素材名称等元信息单独复制。导出、手动保存和自动恢复仍写完整地图，绝不将内部 `editor-image-*` 引用输出为素材图片数据。

这只是内存层拆分，尚未切换到 IndexedDB、Blob 外置或资源包格式。本地存储配额、图片编码和导入文件大小限制不变；浏览器存储不足仍需导出备份，不能通过新图片池突破原限制。

### 差量命令与事务

`EditorHistory` 保存前后差量。普通坐标、标题和参数修改只记录改变的字段；数组插入/删除或键集合/顺序变化会记录该数组或父节点的前后元数据，因此导入替换等操作可能包含较大的元数据块，但不包含图片载荷。

操作结束提交一条命令；无数据变化不新增历史、不清空重做。撤销/重做先在私有候选上验证全部前置状态并应用，完成图片引用解析后才替换模型和转移命令。任一步失败均保留当前地图与两个历史栈。

没有引入持久化命令日志、跨页事务锁、协作编辑或语义合并。历史不写入文件或草稿，刷新后清空；画布交互仍使用短期索引，长期对象身份使用 `objectId`。

### 内存预算与回收

最多 50 条命令，差量数据约 8MiB 预算；图片字符串约 16MiB 软预算。超过预算时优先裁掉较旧历史/最远的重做，保护当前地图、已保存/恢复基线、活动事务及最近的一条历史。若被保护的引用本身超出预算，不强行删除所需图片，因此不是硬性浏览器内存上限。

历史截断或新分支清空重做后，回收不再被模型、状态基线、拖动/滑块事务或命令引用的图片。图片计数包含为撤销/重做及保存基线保留的载荷，可能大于当前素材列表数量。纹理解码、DOM、Phaser 纹理和其他运行内存不包含在估算里。

### 旧地图身份迁移

版本 1 文件新增可选 `objectId`；平台、星星、敌人、装饰、出生点、检查点、终点统一使用。缺失时按类型与原位置索引确定性补齐，并避开已有编号；旧数组星星转为对象。补齐后删除前序对象或重新排序不重新编号，重复解析保持稳定。

编号仅允许 1～64 个字母、数字、下划线或连字符；显式非法/重复编号拒绝导入，不静默覆盖。编号只保证地图内唯一，不保证不同地图全局唯一。平台原 `id` 仍为运行时兼容字段，解析时可重建；不要把它与稳定的 `objectId` 混淆。场景图层继续使用原有稳定 `id`，不参与玩法对象编号空间。

## 浏览器人工验收（待执行）

1. 上传真实 PNG，连续移动星星/平台至少 50 次，完整撤销再重做；图片不丢失，历史计数正确，回保存状态不再提示未保存。
2. 导入使用相同素材 ID、不同图片内容的两张地图，反复撤销/重做，确认每次恢复正确图片，而非后一张覆盖前一张。
3. 批量复制敌人、平台和装饰，删除部分对象，导出再导入；确认外观、攻击参数、碰撞和 `objectId` 正确。
4. 打开自己的旧地图及旧裸草稿，保存、刷新、导出再导入，编号不反复变化，背景和素材仍可用。
5. 使用浏览器性能工具记录连续操作、导入多张图、新分支后的内存趋势；需观察垃圾回收后结果，不用顶栏字符串估算替代堆快照。
6. 验证存储空间不足时仍阻止离开，导出能救援；进入试玩再返回编辑，确认场景无异常。真实触屏操作另行验收。
