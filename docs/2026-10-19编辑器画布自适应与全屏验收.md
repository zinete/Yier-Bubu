# 画布高度自适应与全屏 · 使用与验收

日期：2026-10-19。解决中间编辑画布只显示为固定 540px 高、底部大块空间闲置，以及无法专注查看画布的问题。只调整视图，不增加地图高度或拉伸图片，不改变对象坐标和碰撞。

## 入口

- **铺满高度（默认）**：将 540 世界单位等比缩放到中间工作区的可用高度，保留上下各 20px 内边距及滚动条空间；长地图横向滚动查看，不会压扁整图。窗口或面板尺寸改变时自动重算，超大屏幕的自动高度缩放不受手动 300% 上限截断。
- **全屏画布**：在应用内容区域内收起两侧菜单，保留顶部浮动视图工具和底部提示；进入时自动铺高。退出按钮或 Esc 恢复菜单和进入前的视图模式、缩放/浏览位置。不是调用浏览器 Fullscreen API，不隐藏浏览器或桌面应用自身的边框。
- **游玩视野**：按当前游戏窗口的相机可视范围等比适配编辑工作区，用蓝色虚线和文字提供范围参考。画布构图比例不合时允许留白，不为填满宽高而变形；画布内容垂直居中。参考框超出地图世界边缘时会被地图 SVG 边界裁切。
- **整图总览**：原「适应视口」更名，缩小查看整张长地图；因此可能有较多留白，是主动选择的总览方式，不再作为默认显示。
- `− / ＋ / 100%` 和 Ctrl/⌘＋滚轮仍可手动缩放；手动模式不在每次窗口变化时强制改回自动比例。随时点「铺满高度」恢复自适应。

## 与实际游玩的比例关系

试玩和编辑器参考使用同一 `worldCameraView` 纯计算：相机缩放为 `min(窗口宽/960, 窗口高/540)`。16:9 为 960×540 基准视野，宽屏增加横向范围，窄屏增加纵向范围；并非所有设备都强制裁成 16:9。

铺高模式保证横纵缩放一致、充分利用中间区域，但保留侧栏时，编辑区宽高比通常不同于整个游戏窗口，因此它显示的是可以横向浏览的地图，不冒充一屏完整试玩。需要检查相机范围时用「游玩视野」，或用「试玩」验证角色跟随、HUD、碰撞和运行效果。蓝色参考框不是可交互对象，不参与选择或导出。

## 交互与生命周期

视图变化不增加撤销、不标记地图未保存、不写入 JSON。首次进入从地图起点开始；全屏放置/选择仍将屏幕坐标映射为原世界网格。进入全屏前若有待应用表单会提醒先处理，避免藏起未提交设置。

拖动/框选中按一次 Esc 先取消当前交互，再按一次退出全屏；没有活动交互时直接退出。布局变化发生在拖动/框选/平移期间会延后到结束时处理，避免半途更换缩放导致错位。ResizeObserver 负责中间区域尺寸变化，window resize 提供回退；退出场景断开观察与取消排队任务，旧回调不操作重新进入的编辑器。

固定高度地图只做等比显示，不通过任意增高地图来填充屏幕。自动高度模式的横向滚动条保留，避免滚动条出现/消失导致高度反复抖动。

## 自动化

- 扩展 `editor-viewport.test.mjs`：高度铺满计算含大屏；横屏、超宽屏、窄屏与竖屏比例；运行真实 CameraManager.attach，验证编辑器参考与相机共用相同计算，含 resize/清理。
- 扩展 EditorScene DOM 用例：1100px / 2400px 高度适配、横纵比例一致、全屏布局样式、进入退出与视图恢复、全屏网格放置和撤销、未提交表单阻止隐藏、游玩参考框尺寸和留白、活动交互延迟缩放、ResizeObserver 清理、旧回调隔离、无观察 API 的 resize 回退。
- 保留现有 14 组测试脚本及菜单、保存、历史、平台、分层、网格回归。`pnpm test`、`pnpm lint`、`pnpm build` 均通过；构建仍有原有的大 chunk 提醒。

以上为单元和 jsdom 自动化，不是浏览器像素布局或真实通关验证。

## 人工验收（待执行）

1. 保存草稿后刷新工坊，确认默认画布利用可用高度，底部仅保留必要边距，不再大块闲置。
2. 最大化/缩小应用窗口、窄屏横竖切换，确认角色和平台不变形；横向浏览长地图，站立线、素材和网格仍匹配。
3. 全屏进入/退出十次，试验按钮与 Esc，菜单可恢复，底部和右上方操作可达；原浏览位置合理保留。
4. 在全屏下放置星星、拖动、复制、撤销；退出后保存、刷新再试玩，地图坐标与碰撞未改变。
5. 检查游玩视野蓝框与同窗口的实际试玩范围；注意它不模拟相机跟随偏移、HUD 或额外地图外区域的背景渲染。
6. 拖动时改变窗口尺寸，再取消或完成；观察无跳变、重复回调或无法退出的状态。桌面高 DPI、触屏和浏览器缩放须另行实测。
